# EventRadar — личный бот

Деплой через общую инфраструктуру Termeet и перенос данных: [infra/DEPLOY.md](infra/DEPLOY.md). Инструкция включает SOPS-секреты проекта, перенос SQLite и вход в новый аккаунт ChatGPT.

Настройки и AI-команды бота доступны только владельцу, указанному в `OWNER_TELEGRAM_ID`, в личном чате. Готовые отчеты можно дополнительно публиковать в выбранную приватную группу или канал. Читает публичные Telegram-каналы, выбирает события по вашим интересам и присылает дайджест. AI работает через подписку ChatGPT Pro с официальной авторизацией Sign in with ChatGPT. `OPENAI_API_KEY`, API-организация и отдельный API-баланс для этого режима не используются. Автоматического переключения на платный API нет.

## Возможности

- Добавление и удаление публичных каналов, список и состояние чтения.
- Редактируемый промпт, выбор города и региона.
- Извлечение событий с датой, временем, местом и регистрацией; ссылка на первоисточник в каждой карточке.
- Ежедневный отчет по вашему времени и часовому поясу, ручной дайджест, пауза. Загрузка каналов и AI-анализ запускаются только при подготовке отчета.
- Обычная пересылка карточки средствами Telegram и кнопка для отправки ссылки на исходный пост. Друзьям не нужен доступ к боту.

Команд дружбы, приглашений, общей рассылки каналов и независимого AI-доступа других пользователей нет. Участники общего чата получают только готовые отчеты, не управляют ботом и не запускают AI. Старые социальные таблицы в существующей базе остаются нетронутыми, но код их не использует. Новая база создается без них. Чтение источников и AI-обработка ограничены подписками владельца.

## Как подключается ChatGPT Pro

Первый вход выполняется на вашем компьютере. EventRadar запускает callback на `127.0.0.1`, генерирует PKCE, state и nonce, затем открывает официальный вход OpenAI. Вы входите в ChatGPT и разрешаете приложению использовать подписку. Пароль вводится только на стороне OpenAI. EventRadar получает собственную OAuth-сессию: cookies браузера и авторизация Codex не читаются.

Приложение проверяет подпись ID token по JWKS OpenAI, issuer, audience, срок действия, nonce и разрешение `chatgpt.tokens.use.direct`. После этого сохраняет отдельную сессию в `data/chatgpt/credentials.json`, права `600`. Каталог имеет права `700`; запись атомарная, обновление refresh token сериализовано межпроцессным lock. Выданный client ID и стабильный host ID сохраняются для повторного входа.

AI-запросы идут на официальный `https://api.openai.com/v1/responses` с OAuth-токеном, `store=false`, `stream=true`. Системные правила передаются через `instructions`. Ответ считается завершенным только после `response.completed`; JSON проверяется Pydantic. Модель выбирается из каталога вашего аккаунта, а не из API-моделей другого тарифа.

При ограничении подписки обработка откладывается и сохраняется в базе. Временная пауза переживает перезапуск. При отзыве или истечении невозобновляемой сессии нужен новый вход. Управление лимитами и доступом: [ChatGPT Settings → Usage](https://chatgpt.com/settings/usage).

Официальные источники: [авторизация](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [модели и streaming](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), [обновление сессий](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions), [собственная VM](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms). Доступность функции и моделей определяется OpenAI; успешная выдача сессии подтверждается реальным входом, а не наличием строки Pro в конфигурации.

## Первый вход на компьютере

Используйте Python 3.12, как в Dockerfile. Поддерживаемый диапазон проекта — 3.12–3.14; aiogram 3.31 не устанавливается на Python 3.15. Обновление pip это ограничение не устраняет.

На macOS можно установить отдельную сборку Python через uv, без замены системного Python:

```bash
brew install uv
uv python install 3.12
cd /Users/kipabelousov/eventradar
uv venv --managed-python --python 3.12 --seed .venv312-uv
uv pip install --python .venv312-uv/bin/python -e .
source .venv312-uv/bin/activate
python -m eventradar.chatgpt_auth --directory data/chatgpt login --no-browser
```

Если `.venv312-uv` уже подготовлено, повторять создание и установку не нужно: выполните только `source .venv312-uv/bin/activate`. Активация требуется в каждом новом терминале. Старое `.venv`, созданное на Python 3.15, не используйте для этого проекта.

Параметр `--no-browser` выводит ссылку, которую нужно вручную открыть в вашем обычном браузере на том же компьютере. Терминал оставьте работающим, чтобы он принял callback OpenAI. Каталоги `.venv*` исключены из Git и Docker context.

В открывшейся странице OpenAI выберите аккаунт с Pro и разрешите ChatGPT plan usage. Терминал сообщит результат. Подключение может занять до 10 минут; при отказе или таймауте повторите login. Действующую сессию при неудачной авторизации код не заменяет. Для выбора другого аккаунта используйте отдельный каталог авторизации, не смешивайте client ID и токены разных регистраций.

Просмотр подключения и доступных моделей не запускает генерацию:

```bash
python -m eventradar.chatgpt_auth --directory data/chatgpt status
python -m eventradar.chatgpt_auth --directory data/chatgpt models
```

Оставьте `CHATGPT_MODEL` пустой для первой видимой модели из каталога или задайте точный slug из вывода `models`. Значение `gpt-4.1-mini` из старой API-версии не переносите автоматически.

Отключение сессии:

```bash
python -m eventradar.chatgpt_auth --directory data/chatgpt logout
```

Команда пытается отозвать refresh token в OpenAI, затем очищает локальные токены. Если отзыв не подтвердился, отключите EventRadar в настройках ChatGPT. Отдельный API-ключ нигде не запрашивается.

## Telegram и переменные

Создайте бота через [BotFather](https://t.me/BotFather). Для чтения публичных каналов нужны API ID и API hash с [my.telegram.org](https://my.telegram.org), а также сессия вашего Telegram-клиента:

```bash
python -m eventradar.session
```

Скрипт сохранит сессию в `data/reader-session.txt`. Ее содержимое — `TELEGRAM_READER_SESSION`. Если читатель и владелец — один аккаунт, его числовой ID отображается скриптом после авторизации. Сессия дает доступ к Telegram-аккаунту: никогда не коммитьте ее.

Заполните `.env.example` и сохраните как GitHub Secret `BOT_ENV` в environment `production`, либо создайте `/srv/eventradar/.env` вручную с правами `600`.

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен нового бота от BotFather |
| `OWNER_TELEGRAM_ID` | Ваш единственный числовой Telegram ID; список ID не поддерживается |
| `TELEGRAM_API_ID` | API ID Telegram-приложения |
| `TELEGRAM_API_HASH` | API hash этого приложения |
| `TELEGRAM_READER_SESSION` | Содержимое файла сессии читателя |
| `CHATGPT_AUTH_DIR` | В контейнере `/data/chatgpt` |
| `CHATGPT_MODEL` | Пусто или точный slug из каталога подключенной подписки |
| `DATABASE_PATH` | В контейнере `/data/eventradar.sqlite3` |
| `DEFAULT_TIMEZONE`, `SOURCE_TIMEZONE` | По умолчанию `Europe/Moscow` |
| `INITIAL_LOOKBACK_DAYS` | История для самого первого отчета, по умолчанию `7` дней |
| `MAX_CHANNELS_PER_USER` | Максимум каналов владельца, по умолчанию `30` |
| `AI_BATCH_SIZE` | Постов в одном AI-запросе, по умолчанию `10`, максимум `20` |
| `AI_BATCH_MAX_CHARACTERS` | Максимум символов публикаций в пакете, по умолчанию `30000` |
| `MAX_PHOTOS_PER_REPORT` | Максимум иллюстраций на один отчет, по умолчанию `3`; `0` отключает картинки. На количество карточек не влияет |
| `MAX_AI_CALLS_PER_DAY` | Локальный дневной лимит запросов, по умолчанию `300` по UTC |

`ALLOWED_USER_IDS`, `OPENAI_API_KEY`, `OPENAI_MODEL`, `GOOGLE_ROUTES_API_KEY`, `POLL_INTERVAL_SECONDS`, `MAX_POSTS_PER_CYCLE` и `MAX_DIGEST_ITEMS` больше не используются. OAuth-токены не кладите в `BOT_ENV`: сервер обновляет их во время работы, а старое значение из GitHub при деплое могло бы затереть обновленную сессию.

## Команды

`/help` содержит полный список. Пример:

```text
/add @business_club
/city Москва
/region Россия, Москва
/schedule 08:30 Europe/Moscow
/prompt Ищу очные встречи с основателями компаний. Нужны дата, время, адрес и регистрация.
/ai
/digest
```

`/add` принимает несколько публичных каналов через пробел: `/add @channel1 @channel2 https://t.me/channel3`. Бот сообщает результат по каждому каналу, пропускает повторы и добавляет корректные каналы, даже если другая ссылка неверна. Лимит каналов сохраняется.

`/pause` и `/resume` управляют отчетами. `/delete_me` удаляет личный профиль из рабочей БД, но не отзывает OAuth: для этого есть `chatgpt_auth logout`.

## Границы реализации

AI извлекает сведения из текста и Telegram-ссылок, не проверяет организатора независимо, не читает афиши через OCR и не открывает сайты регистрации. Редактирование источников отслеживается в последних 30 постах. Дедупликация между разными каналами консервативная. Расписание может сдвигаться на время обработки источников.

Доставка Telegram не имеет exactly-once: авария между отправкой и сохранением результата может привести к повтору. Healthcheck — локальный heartbeat процесса, не проверка доступности OpenAI/Telegram. Все персональные данные и сессии требуют закрытого доступа к диску. Резервные копии SQLite автоматически не удаляют прежние персональные записи при `/delete_me`.

Python 3.12, aiogram, Telethon, HTTPX, PyJWT с cryptography, Pydantic и SQLite WAL. Один процесс и одна реплика. Сборки, тесты, линтеры, форматтеры и проверки не запускаются без отдельного запроса владельца. Реальное подключение требует завершенного согласия в OpenAI; до этого нельзя утверждать, что подписка уже работает.

## HTTPS и доверенные сертификаты

HTTPX использует системное хранилище сертификатов через truststore: на macOS это позволяет работать с уже доверенными системными сертификатами. В серверном окружении используется системное хранилище платформы. При явно заданных `SSL_CERT_FILE` или `SSL_CERT_DIR` применяется указанный CA bundle/каталог. Проверка сертификата и имени сервера остается включенной.

Если `models` возвращает ConnectError, повторная авторизация обычно не нужна: команда теперь выводит безопасное пояснение, отличая TLS, DNS и таймауты. Токены, заголовки и URL запросов в диагностике не печатаются.

## Когда читаются каналы и расходуется AI

Фоновая задача раз в минуту проверяет только локальное расписание. До времени отчета она не загружает публикации и не вызывает AI. Подготовка запускается по расписанию или явно через `/digest`.

Период отчета: от `last_report_at` предыдущего успешно отправленного отчета включительно до момента начала нового отчета исключительно. Для первого отчета берутся последние `INITIAL_LOOKBACK_DAYS` дней. Сообщения, пришедшие во время подготовки, остаются на следующий отчет. Каналы читаются с полной пагинацией без ограничения в 100 сообщений. Если канал недоступен или Telegram требует паузу, период не закрывается и AI-анализ не начинается.

Извлечение событий и отбор по интересам объединены: до 10 постов в одном запросе, также действует ограничение размера текста пакета. Ответ обязан учитывать каждый входной пост, в том числе пустым списком рекомендаций. Результаты кешируются по тексту, интересам, региону и модели; при повторе незавершенного отчета готовые пакеты не оплачиваются повторными AI-запросами.

После анализа отправляются все подходящие карточки и итог отчета. Только после успешной отправки итога обновляется `last_report_at`. Лимит количества карточек не отбрасывает остаток периода. При сбое доставки сохраняются уже отправленные карточки, а незакрытый период обрабатывается при следующем отчете. Повторная автоматическая попытка — в следующий день по расписанию; немедленную можно запросить через `/digest`. Неудача не запускает анализ снова каждую минуту.

Ручной отчет тоже закрывает успешно обработанный период. Следующий отчет по расписанию берет только новые сообщения после него. Изменение промпта применяется к новому/еще не закрытому периоду, не пересматривает автоматически всю старую историю. При обновлении старой базы граница по возможности восстанавливается из времени последней доставленной карточки; если истории доставки нет, используется первичная глубина.

## Оформление, Яндекс Карты и иллюстрации

Карточки используют иконки для даты, места, регистрации, объяснения отбора и источника. Ссылка на карту ведет в поиск Яндекс Карт по месту события. Домашний адрес в ссылку не включается; ключ карт не требуется для обычной веб-ссылки.

Бот прикладывает по одной фотографии из первых подходящих исходных постов, максимум `MAX_PHOTOS_PER_REPORT` на отчет. Это не ограничение числа событий. Из одного исходного поста иллюстрация берется один раз. Обрабатываются только Telegram-фотографии до 8 MiB; произвольные URL не загружаются. Защищенные от копирования публикации и каналы не используются для копирования медиа. Если фото нет, оно недоступно или Telegram отклонил загрузку, вся карточка отправляется текстом. Картинки не анализируются AI, дополнительных AI-запросов для них нет.

При длинной карточке фотография получает первую часть текста в подписи, а оставшийся текст идет следом с кнопками; сведения не обрезаются из-за лимита подписи Telegram. Просмотреть сохраненную карточку в новом оформлении без AI и без изменения периода отчета: `/preview ID`.

## Общая группа или канал только для публикации

Создайте приватную группу/канал и пригласите нужных участников. Добавьте туда `@eventradar_personal_bot`. В канале назначьте бота администратором с правом публикации сообщений. Для группы бот должен иметь возможность отправлять сообщения и фотографии. Владелец бота должен быть администратором выбранного чата. Публичные чаты с username не подключаются, чтобы случайно не опубликовать личный отчет открыто.

Все дальнейшие действия — в личном чате с ботом:

1. Отправьте `/destination`. Бот покажет чаты, в которые вы добавили его или изменили его статус после обновления.
2. Выберите нужный чат кнопкой. На этом этапе сообщения в него еще не отправляются.
3. Отправьте `/publish`, чтобы опубликовать уже готовый отчет. Новый AI-анализ не запускается. Для первого подключения можно использовать сохраненные карточки предыдущего личного отчета.
4. Следующие личные отчеты будут автоматически копироваться в выбранный чат после успешной подготовки.

Если бот был добавлен до обновления и чат не появился, измените его статус администратора или добавьте бота заново, затем повторите `/destination`. Для известного числового ID доступна команда `/destination -1001234567890`. Отключение: `/destination off`. Перед подключением проверяются тип чата, ваша роль и права бота; перед публикацией также проверяется, что чат не стал публичным.

В общем чате нет команд управления: `/add`, `/prompt`, `/schedule`, `/digest` и прочие работают только у владельца в личной переписке. Участники не подключаются к вашей подписке и не запускают AI-запросы. Бот не сохраняет и не отправляет в AI обычную переписку группы. Домашний адрес, личная оценка дороги и отзывы в общие карточки не включаются. Отчет остается подборкой по вашим источникам и интересам.

Для публикации используется сохраненный снимок отчета. При сбое можно повторить `/publish`: отправка продолжится с сохраненной карточки, а повторно завершенный отчет не дублируется. Сбой публикации в общий чат не отменяет успешно доставленный личный отчет и не вызывает повторный AI-анализ. После аварии между отправкой сообщения и записью результата возможен повтор отдельной карточки — Telegram не предоставляет exactly-once для sendMessage/sendPhoto.

[Условия Sign in with ChatGPT](https://openai.com/policies/sign-in-with-chatgpt-terms/) запрещают выполнять запросы других пользователей за счет подписки владельца. Поэтому общий чат получает результат ваших собственных запросов/автоматизаций; многопользовательский AI-сервис с одной Pro-сессией здесь не включается.
