# EventRadar

Личный Telegram-бот для небольшого круга друзей: читает публичные каналы, отбирает публикации по персональным интересам, присылает ежедневные дайджесты и помогает приглашать друг друга на события.

## Что реализовано

- Закрытый доступ по Telegram ID; отдельные интересы, каналы, город, регион, адрес и расписание каждого пользователя.
- Добавление, удаление и список публичных каналов. Подписки внутри бота не меняют личные подписки Telegram.
- Отдельный Telethon-клиент читает канал один раз для всех подписчиков. Первичная история за последние 7 дней, последующее чтение по курсору, обновление последних 30 публикаций для учета правок и удалений в этом окне.
- Извлечение нескольких событий из поста, ссылок из Telegram entities, дат с часовыми поясами и признака отмены через OpenAI Structured Outputs. Если событий нет, сохраняется обычная публикация: пользовательский промпт может разрешить и ее.
- Персональная фильтрация с кешем решений. Отсутствующие сведения не дополняются догадками. Промпт по умолчанию требует очного события, конкретного места, времени и ссылки регистрации.
- Ежедневный отчет по локальному времени, ручной дайджест, пауза и возобновление. Неизмененные доставленные карточки не повторяются. Изменение интересов пересчитывает еще не доставленные материалы.
- Сезонная еженедельная занятость, интервалы через полночь, исключение пересекающихся событий. При неизвестной длительности используется явно обозначенное предположение: 2 часа.
- Приблизительное время дороги общественным транспортом и число пересадок от AI, без транспортных API. Адрес передается OpenAI только после `/routing on`; оценка показывается диапазоном с пометкой об отсутствии карт и расписания. Ссылка на карту не содержит домашний адрес, приглашения не запускают персональную оценку получателя.
- Дружба с подтверждением, приглашения конкретному другу с ответом «Пойду / Не смогу».
- Выбор конкретных каналов для предложения другим участникам, согласившимся получать предложения. Для каждого получателя исключаются уже имеющиеся подписки; автоматической подписки нет.
- Посещение, личный отзыв, публикация отзыва друзьям, история. Старые карточки неизменяемые: обновление источника не подменяет событие в ранее отправленном приглашении.
- SQLite WAL на постоянном Docker volume, очередь социальных уведомлений с повторами, дневной лимит AI-запросов, закрытые секреты и удаление профиля.
- Деплой исходников по SSH с локальной сборкой на сервере, резервной копией базы, ожиданием здоровья и попыткой отката на предыдущий локальный образ. Registry не нужен.

Код написан без запуска сборок, тестов, линтеров, форматтеров и проверок по требованию владельца. Он требует проверки с реальными интеграциями перед использованием в production. Зависимости ограничены совместимыми диапазонами, lock-файл пока не создавался; сборки могут получать новые версии в этих диапазонах.

## Архитектура

Python 3.12, aiogram 3, Telethon 1, OpenAI Responses API, Pydantic и aiosqlite. Один процесс и одна реплика. Никаких открытых HTTP-портов: Bot API работает через long polling.

`reader.py` отвечает за загрузку и извлечение, `ai.py` — только за AI, `domain.py` — за форматы и календарные правила, `service.py` — за дайджесты и доставку, `handlers.py` — за Telegram-команды. Соединения SQLite открываются на короткие операции; сеть не вызывается внутри транзакций. Вызовы одного пользователя выполняются последовательно. Общий лимит AI резервируется в базе до запроса и сохраняется после перезапуска.

Дневной лимит — число логических AI-вызовов по UTC, не денежный лимит и не лимит токенов. SDK может один раз повторить сетевой запрос. Ограничьте расходы и на стороне OpenAI. Источники, адреса и пользовательские промпты не пишутся в application logs.

## OpenAI и подписка ChatGPT

Приложение использует серверный `OPENAI_API_KEY`. Пользователи бота не входят в аккаунт владельца и не получают этот ключ.

API-организация — техническое пространство OpenAI для ключей, проектов и расходов. Ее может использовать один человек: компания, юридическое лицо и командная подписка для этого не требуются. При первом входе в API Platform может потребоваться создать или выбрать такое личное пространство; для официального API оно необходимо. Для первого знакомства можно использовать существующий Default project, для сервера выделить проект EventRadar и ключ service account.

У подходящих подписок ChatGPT Pro и Business могут быть API-кредиты. Их нужно активировать, привязав подписку к принадлежащей вам API-организации. Это отдельное право использования API с собственными лимитами; наличие обычной подписки само по себе не дает произвольному приложению доступ через браузерную сессию. Уточните доступность в своем Billing. После активации используйте ключ проекта именно привязанной организации. Если льгота недоступна, необходимы отдельные API-кредиты.

Официальные источники: [API credits for ChatGPT subscribers](https://developers.openai.com/api/docs/guides/chatgpt-api-credits), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [authentication](https://learn.chatgpt.com/docs/auth). Не копируйте cookies ChatGPT или `auth.json` Codex на сервер бота.

## Настройка Telegram

1. Создайте нового бота через [BotFather](https://t.me/BotFather). Его токен — `TELEGRAM_BOT_TOKEN`.
2. Получите `api_id` и `api_hash` приложения на [my.telegram.org](https://my.telegram.org). Они нужны читателю Telethon, не самому Bot API.
3. Для чтения используйте отдельный Telegram-аккаунт с доступом к нужным публичным каналам. В этой версии приватные каналы и группы намеренно не поддерживаются. Бот не подписывает читателя на все каналы автоматически и не читает его личные чаты.
4. На доверенной машине установите зависимости проекта и выполните интерактивную авторизацию читателя. Это ручные команды; агент их не запускал:

```bash
cd /Users/kipabelousov/eventradar
python3.12 -m venv .venv
source .venv/bin/activate
pip install .
python -m eventradar.session
```

Скрипт спросит API ID, API hash, номер телефона, код Telegram и пароль 2FA, если он включен. Результат сохранит в `data/reader-session.txt` с закрытыми правами. Содержимое файла целиком — `TELEGRAM_READER_SESSION`. Файл и каталог исключены из Git и Docker build context. Сессия дает доступ к Telegram-аккаунту: храните ее как пароль. При утечке завершите соответствующую сессию в Telegram → Устройства и создайте новую.

5. Откройте своего бота и отправьте `/start`. Даже без допуска он сообщит ваш числовой ID. Добавьте ID владельца и друзей в `ALLOWED_USER_IDS`, затем передеплойте. Каждый друг должен сам запустить бота: бот не может первым начать переписку.

Ограничения описаны в [Telegram Bots FAQ](https://core.telegram.org/bots/faq) и [документации Telethon](https://docs.telethon.dev/en/stable/modules/client.html).

## Переменные приложения

Возьмите `.env.example`, заполните значения и сохраните весь файл в GitHub Secret `BOT_ENV` окружения `production`. Альтернатива — вручную создать `/srv/eventradar/.env` с правами `600`: если `BOT_ENV` не задан, пайплайн сохранит серверный файл.

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен нового бота от BotFather |
| `ALLOWED_USER_IDS` | Числовые ID владельца и друзей через запятую, например `123456789,987654321`; пустое значение не допускается |
| `TELEGRAM_API_ID` | Числовой API ID с my.telegram.org |
| `TELEGRAM_API_HASH` | API hash того же Telegram-приложения |
| `TELEGRAM_READER_SESSION` | Содержимое `data/reader-session.txt` после интерактивного входа |
| `OPENAI_API_KEY` | Ключ отдельного проекта вашей API-организации, например ключ с префиксом `sk-proj-` |
| `OPENAI_MODEL` | Модель с поддержкой Structured Outputs; начальное значение `gpt-4.1-mini`, доступность проверьте в своей организации |
| `DEFAULT_TIMEZONE` | Начальный часовой пояс новых пользователей, `Europe/Moscow` |
| `SOURCE_TIMEZONE` | Зона анонсов, если в публикации не указана другая, `Europe/Moscow` |
| `DATABASE_PATH` | Оставьте `/data/eventradar.sqlite3`, чтобы база находилась на Docker volume |
| `POLL_INTERVAL_SECONDS` | Период загрузки каналов, по умолчанию `300` |
| `INITIAL_LOOKBACK_DAYS` | Глубина истории нового канала, по умолчанию `7`, максимум `30` |
| `MAX_CHANNELS_PER_USER` | Лимит подписок пользователя, по умолчанию `30` |
| `MAX_AI_CALLS_PER_DAY` | Общий дневной предел логических AI-вызовов, по умолчанию `300` |
| `MAX_POSTS_PER_CYCLE` | Максимум новых сообщений каждого канала и максимум извлечений за цикл, по умолчанию `100` |
| `MAX_DIGEST_ITEMS` | Карточек в одном дайджесте, по умолчанию `20` |

Google Routes не используется, отдельный ключ карт не нужен. После `/routing on` OpenAI получает точку отправления и место события и дает грубый диапазон времени и пересадок по общим знаниям. Карты, геокодирование, пробки и расписания не запрашиваются. Если адрес неоднозначен или модель не может оценить дорогу, числовая оценка отсутствует. Это ориентир для выбора события, не готовый маршрут. Оценка кешируется на 7 дней для пользователя, адресов, времени события и модели, использует общий дневной лимит AI. При обновлении старой базы согласие на передачу адреса сбрасывается: `/routing on` нужно включить заново для нового провайдера.

GitHub Variables не подходят для секретных значений: используйте именно Secrets. В `BOT_ENV` строки в dotenv-формате `KEY=value`, без `export`; значения с пробелами можно заключать в одинарные кавычки. Не добавляйте настоящие секреты в `.env.example`, workflow, issue или README.

## Отправка кода с компьютера по HTTPS

Ошибка `Permission denied (publickey)` означает, что GitHub не принял пользовательский SSH-ключ компьютера. Подтверждение host key проверяет сервер GitHub, но не дает вашему ключу доступ к аккаунту. Ошибка `remote origin already exists` означает, что `origin` уже добавлен: нужен `set-url`, а не повторный `add`.

```bash
cd /Users/kipabelousov/eventradar
git remote set-url origin https://github.com/Kiryshka1922/eventradar.git
```

Для входа через браузер можно использовать официальный GitHub CLI (если он еще не установлен, на macOS с Homebrew: `brew install gh`):

```bash
gh auth login --hostname github.com --git-protocol https --web --scopes workflow
gh auth setup-git
git push --set-upstream origin main
```

Войдите в аккаунт Kiryshka1922. Дополнительное разрешение `workflow` нужно для отправки файла GitHub Actions. Пароль аккаунта для Git по HTTPS не используется; GitHub CLI сохраняет авторизацию в системном хранилище, если оно доступно. Эти команды выполняются владельцем вручную; код агентом не отправлялся. Авторизация браузера и Git — разные сеансы. Настройка HTTPS на компьютере не меняет SSH-схему серверного деплоя ниже.

[GitHub CLI login](https://cli.github.com/manual/gh_auth_login), [смена remote URL](https://docs.github.com/en/get-started/git-basics/managing-remote-repositories).

## Два SSH-ключа: зачем и куда

Есть два независимых соединения:

| Соединение | Где приватный ключ | Где публичный ключ |
| --- | --- | --- |
| GitHub Actions → сервер | GitHub Secret `SSH_PRIVATE_KEY` | `/home/eventradar/.ssh/authorized_keys` сервера |
| Сервер → приватный GitHub-репозиторий | `/home/eventradar/.ssh/github_eventradar` сервера | GitHub → eventradar → Settings → Deploy keys, только чтение |

Также `SSH_KNOWN_HOSTS` содержит публичный **ключ самого SSH-сервера**, а не ключ пользователя. Он позволяет Actions проверить, что соединение идет на вашу машину. Никогда не выключайте `StrictHostKeyChecking`.

### 1. Пользователь на сервере

Ниже команды для Ubuntu/Debian, выполняемые администратором сервера вручную. Существующий Termeet и его пользователей менять не требуется.

```bash
sudo adduser --disabled-password --gecos '' eventradar
sudo install -d -m 700 -o eventradar -g eventradar /home/eventradar/.ssh
sudo install -d -m 750 -o eventradar -g eventradar /srv/eventradar
```

Установите Docker Engine, Compose plugin и Git по официальной инструкции вашего дистрибутива. Для выбранного пайплайна пользователь должен выполнять Docker без интерактивного sudo:

```bash
sudo usermod -aG docker eventradar
```

Применение группы требует нового SSH-сеанса. Членство в группе `docker` фактически дает полномочия root на машине. Используйте выделенного пользователя и доверенный сервер; rootless Docker — альтернатива, требующая отдельной настройки daemon/socket. В GitHub environment `production` можно включить approval перед деплоем.

### 2. Ключ GitHub Actions → сервер

На вашем компьютере создайте отдельную пару без passphrase для автоматизации. Не используйте личный основной SSH-ключ:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/eventradar_actions -C eventradar-github-actions -N ''
```

Содержимое `~/.ssh/eventradar_actions.pub` добавьте одной строкой в `/home/eventradar/.ssh/authorized_keys` сервера. Перед `ssh-ed25519` можно поставить ограничение `restrict`, чтобы запретить forwarding и PTY. Существующие ключи в файле сохраняйте. После добавления:

```bash
sudo chown eventradar:eventradar /home/eventradar/.ssh/authorized_keys
sudo chmod 600 /home/eventradar/.ssh/authorized_keys
```

Содержимое файла `~/.ssh/eventradar_actions` **целиком**, включая строки `BEGIN OPENSSH PRIVATE KEY` / `END OPENSSH PRIVATE KEY`, сохраните в GitHub Secret `SSH_PRIVATE_KEY`. Сам приватный ключ Actions на сервер добавлять не нужно.

### 3. Ключ сервер → GitHub

На сервере:

```bash
sudo -u eventradar ssh-keygen -t ed25519 -f /home/eventradar/.ssh/github_eventradar -C eventradar-readonly-github -N ''
```

Добавьте содержимое `/home/eventradar/.ssh/github_eventradar.pub` в [Deploy keys репозитория](https://github.com/Kiryshka1922/eventradar/settings/keys). **Allow write access выключен**. Приватный файл остается только на сервере, в GitHub Secrets его класть не надо.

Создайте `/home/eventradar/.ssh/config`, владелец `eventradar`, права `600`:

```sshconfig
Host github.com
  HostName github.com
  User git
  IdentityFile /home/eventradar/.ssh/github_eventradar
  IdentitiesOnly yes
  StrictHostKeyChecking yes
```

Добавьте проверенный host key GitHub в `/home/eventradar/.ssh/known_hosts`. Сверьте fingerprint по [официальной странице GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints). Один `ssh-keyscan` без независимой сверки не удостоверяет подлинность сервера.

Теперь клонируйте код в подготовленный каталог:

```bash
sudo -u eventradar git clone git@github.com:Kiryshka1922/eventradar.git /srv/eventradar
```

### 4. Host key вашего сервера

Через доверенную консоль сервера получите `/etc/ssh/ssh_host_ed25519_key.pub`. Для порта 22 `SSH_KNOWN_HOSTS` должен содержать строку вида `your-server.example ssh-ed25519 AAAA...`; для нестандартного порта — `[your-server.example]:2222 ssh-ed25519 AAAA...`. Используйте в начале тот же hostname/IP, что и в `SSH_HOST`. Приватный `/etc/ssh/ssh_host_ed25519_key` никуда не копируйте.

### 5. GitHub Actions

Создайте environment `production` в [настройках репозитория](https://github.com/Kiryshka1922/eventradar/settings/environments). В нем задайте Secrets:

| Secret | Что положить |
| --- | --- |
| `SSH_HOST` | IP или DNS сервера, без `https://` и без порта |
| `SSH_USER` | `eventradar` |
| `SSH_PRIVATE_KEY` | Приватный ключ Actions из шага 2 |
| `SSH_KNOWN_HOSTS` | Проверенная строка host key из шага 4 |
| `BOT_ENV` | Весь заполненный `.env.example`; либо оставьте этот secret отсутствующим и заведите `/srv/eventradar/.env` вручную |

Repository Variables:

| Variable | Значение |
| --- | --- |
| `SSH_PORT` | SSH-порт, обычно `22`; если не задан, используется `22` |
| `DEPLOY_ENABLED` | `true` только после подготовки сервера, deploy key и секретов |

`DEPLOY_ENABLED` задавайте на уровне **репозитория**, потому что условие job вычисляется до загрузки environment. После настройки откройте Actions → Deploy EventRadar → Run workflow для `main`. Последующие push в `main` запускают деплой автоматически. Образы не отправляются в registry; ключи и `.env` не попадают в Docker build context.

Пайплайн получает `origin/main` и переключается на точный SHA workflow, а не на произвольный текущий HEAD после `git pull`. Это дает ожидаемую семантику обновления кода и защищает от выкатывания другого коммита. Устаревший workflow пропускается, если `main` уже продвинулся. Грязный серверный checkout не перезаписывается. Файлы редактируйте локально и отправляйте через Git.

При наличии `BOT_ENV` он передается по SSH в `.env.pending`, затем атомарно становится `.env`. При неудаче скрипт пытается восстановить старые `.env`, checkout и локальный образ. Предыдущие образы автоматически не удаляются. Резервные копии SQLite создаются перед заменой контейнера в `/data/backups`, сохраняются последние 10. При будущих несовместимых миграциях откат приложения требует отдельного плана восстановления БД; автоматический restore базы сейчас не выполняется.

## Примеры использования

```text
/add @business_club
/city Москва
/region Россия, Москва
/schedule 08:30 Europe/Moscow
/prompt Ищу очные встречи с основателями компаний в Москве. Нужны дата, время, точный адрес и регистрация. Исключай онлайн, рекламу курсов и прошедшие мероприятия.
/block 3 00:00 00:00 9 5
/address Москва, улица и номер дома
/routing on
/digest
```

`/block 3 00:00 00:00 9 5` исключает всю среду с сентября по май включительно каждый год, летом ограничение не действует. Для разовых дат отдельный интерфейс пока не реализован. После добавления друга через `/friend ID` он подтверждает дружбу кнопкой; затем выберите «Пригласить друга» под карточкой события.

Полный справочник команд доступен через `/help`. Изменение интересов не редактирует уже отправленные Telegram-сообщения. Повторные отчеты содержат еще не доставленные подходящие публикации и обновленные версии источников.

## Эксплуатационные границы

- AI извлекает сведения из поста, но не проверяет существование события независимо, доступность регистрации или достоверность организатора. Первичный пост всегда доступен по ссылке. Если обязательные детали находятся только в картинке или на внешнем сайте, бот их не извлекает: OCR и обход сайтов в этой версии отсутствуют.
- Анонсы, написанные без города или неоднозначного года, могут потребовать уточнения у организатора. Единая `SOURCE_TIMEZONE` подходит первоначальному набору московских каналов; каналы из разных зон должны указывать зону в тексте. Промпт не заменяет валидатор истинности фактов.
- Изменения и удаления старше окна последних 30 постов автоматически не обнаруживаются. Новая версия поста получает новые карточки; старые приглашения не переписываются. Связывания отмен из отдельного нового поста с предыдущим анонсом пока нет.
- Дедупликация внутри отчета консервативная: совпадение заголовка, времени и места. Разные формулировки одного события могут давать несколько карточек. Между отчетами учитывается доставка конкретной версии карточки, не глобальная идентичность мероприятия.
- При исчерпании дневного AI-лимита очередь обработки сохраняется. Рассылка сообщает, если часть постов еще обрабатывается. Не доставленные из-за лимита карточки попадут в следующий отчет. Первый дайджест после добавления канала может быть пустым до завершения первого чтения.
- Telegram не предоставляет идемпотентный ключ `sendMessage`. Между успешной отправкой и записью результата в БД при аварии возможно повторное сообщение. Система не обещает exactly-once. Социальные уведомления имеют постоянную очередь, не более 10 попыток; отказ Telegram или блокировка бота завершает соответствующую доставку.
- Расписание обрабатывается раз в минуту плюс время обработки источников/предыдущих отчетов. При остановке сервера догоняется текущий день, многодневные пропущенные отчеты отдельно не воспроизводятся. Сезонная занятость учитывает длительность события, но не время дороги.
- Healthcheck проверяет работу процесса через локальный heartbeat, не доступность внешних провайдеров. Недоступность отдельного канала видна в `/channels`. Docker restart policy перезапускает завершившийся процесс; статус unhealthy сам по себе Docker не перезапускает.
- База и резервные копии содержат персональные данные. Шифрование диска, внешние резервные копии и их срок хранения настраиваются на сервере. Удаление профиля чистит рабочую БД, но не отправленные сообщения, старые backup-файлы и ранее опубликованные отзывы в чужих чатах. Общие публичные посты хранятся до административной очистки; автоматического срока удаления пока нет.
- Доступ рассчитан на небольшую allowlist и одну реплику. Для расширения аудитории понадобятся учет квот по пользователям, отдельный ingestion worker, мониторинг доставки и миграции базы.

## Файлы

- `eventradar/` — приложение и схема SQLite.
- `.env.example` — полный перечень переменных без секретов.
- `compose.yaml`, `Dockerfile` — запуск с постоянным volume и непривилегированным пользователем.
- `infra/deploy.sh` — серверная сборка и переключение релиза.
- `.github/workflows/deploy.yaml` — SSH-пайплайн без registry.

Локальный `.env`, сессии, ключи и база не коммитятся. `.cursorignore` не создается и не изменяется.
